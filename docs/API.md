# HTTP API Contract

This document is the authoritative contract for the eino_agent Go backend, derived directly
from the handler code on branch `refactor/overhaul`. It is intended for building the new
TypeScript frontend: field names and nesting below match the Go `json` tags exactly.

Note: `docs/swagger.json` / `docs/swagger.yaml` are generated by swaggo from code
annotations and may lag behind this document. When the two disagree, trust this document.

## 1. Overview

### Base URL

All API routes live under `/api/v1`. Health probes live at the server root (`/health`,
`/health/live`, `/health/ready`). Default listen address is configured server-side
(e.g. `http://localhost:8080`).

### Trace ID

Every response carries an `X-Trace-ID` header. A client may supply its own `X-Trace-ID`
request header; otherwise the server generates a UUID. The same value appears in the
`trace_id` field of error bodies and chat responses.

### Authentication

- JWT bearer auth. Obtain a token via `POST /api/v1/auth/login`, then send
  `Authorization: Bearer <access_token>` on all `/api/v1` routes except `POST /auth/login`.
- Tokens are HS256 JWTs signed server-side. Claims: `sub` (username), `role`
  (`admin` | `user`), `tenant_id` (int), `exp`, `iat`.
- When server config `AUTH_ENABLED=false`, all auth checks are bypassed: every request is
  treated as user `anonymous` with role `admin`, tenant `1`. The frontend should still
  handle 401s for deployments where auth is on.
- Global roles gate a few routes via `RequireRole("admin")` (marked **Role: admin** below).
  Knowledge-base-scoped routes instead check a per-KB role: `viewer` < `editor` < `admin`
  (marked **KB role:** below). A user's effective KB role comes from KB shares / tenant
  membership; global `admin` bypasses per-KB checks.

### Error envelope

Every non-2xx JSON error uses one envelope (defined in `internal/handler/middleware.go`):

```json
{
  "error": {
    "code": "not_found",
    "message": "human-readable message (usually Chinese)",
    "trace_id": "0f8e...",
    "details": {}
  }
}
```

`trace_id` and `details` are omitted when empty. `code` is derived from the HTTP status:

| HTTP | code | HTTP | code |
|---|---|---|---|
| 400 | `invalid_argument` | 422 | `unprocessable` |
| 401 | `unauthenticated` | 429 | `rate_limited` |
| 403 | `permission_denied` | 502 | `upstream_error` |
| 404 | `not_found` | 503 | `unavailable` |
| 409 | `conflict` | 504 | `upstream_timeout` |
| 413 | `payload_too_large` | other 5xx | `internal` |

### Pagination

List endpoints that paginate accept query params `page` (1-based, default 1) and
`page_size` (endpoint-specific default and max, see each route). Responses return
`page`, `page_size`, and `total` alongside the items array. Endpoints without
pagination are noted.

## 2. Health

### `GET /health` and `GET /health/ready`

No auth. Probes dependencies concurrently (3s timeout). `200` when all required
components are up; `503` when a required component is down.

```json
{
  "status": "ok",                     // ok | degraded | down
  "timestamp": "2024-01-01T00:00:00Z",
  "components": {
    "database":     {"status": "ok", "required": true,  "latency_ms": 2},
    "vector_store": {"status": "ok", "required": true,  "latency_ms": 1},
    "redis":        {"status": "disabled", "required": false},
    "llm":          {"status": "ok", "required": true},
    "embedding":    {"status": "ok", "required": true},
    "docreader":    {"status": "ok", "required": false},
    "import_queue": {"status": "ok", "required": false},
    "graphrag":     {"status": "disabled", "required": false}
  }
}
```

Component entry: `status` (`ok` | `degraded` | `down` | `disabled`), `required` (bool),
`latency_ms` (int, only for live probes), `error` (string, only when down).
Overall status is `down` (HTTP 503) if any required component is `down`, else `degraded`
if any optional component is `down`, else `ok`.

### `GET /health/live`

No auth, no dependency checks. `200`:

```json
{"status": "ok", "timestamp": "2024-01-01T00:00:00Z"}
```

## 3. Auth

### `POST /api/v1/auth/login`

No auth required. Rate limited per client IP: 10 requests/minute, burst 3
(`429 rate_limited` when exceeded).

Request:

```json
{"username": "admin", "password": "secret"}
```

Both fields required. `200`:

```json
{
  "access_token": "<jwt>",
  "token_type": "Bearer",
  "expires_in": 43200,
  "user": {"id": "admin", "role": "admin", "tenant_id": 1}
}
```

`expires_in` is seconds (`ACCESS_TOKEN_EXPIRE_MINUTES * 60`). Errors: `400` when auth is
disabled server-side or fields missing; `401` on bad credentials.

### `GET /api/v1/auth/me`

Auth required. `200`:

```json
{"user": {"id": "admin", "role": "admin", "tenant_id": 1}}
```

## 4. Chat

### Request body (shared by both chat endpoints)

```json
{
  "query": "...",                  // message text; takes precedence over message
  "message": "...",                // alternative to query
  "session_id": "...",             // optional; continue a session
  "use_agent": false,              // legacy; forces agentic mode when true
  "knowledge_base_ids": ["kb1"],   // optional; defaults to all KBs the caller can view
  "document_ids": ["doc1"],        // optional; restrict retrieval to documents
  "mode": "pipeline",              // "pipeline" (default) | "agentic"
  "top_k": 5,
  "temperature": 0.7,
  "force_citation": false,
  "enable_long_term": true
}
```

Notes:

- `query` or `message` is required; `query` wins when both are set.
- `mode` is normalized server-side: anything but `"agentic"` (case-insensitive) becomes
  `"pipeline"`. `use_agent: true` overrides `mode` to agentic. A medium-risk prompt-guard
  verdict silently downgrades agentic to pipeline.
- `top_k` and `temperature` are currently accepted but not forwarded to the chat service.
- `enable_long_term` is a tri-state pointer: omit it to use the server default.
- If `session_id` is supplied it must exist and belong to the caller (`403`/`404` otherwise).
- Prompt-guard may reject high-risk input with `400`.

### `POST /api/v1/chat` — non-streaming

Auth required. `200`:

```json
{
  "answer": "...",
  "references": [
    {"id": "doc-id", "content": "...", "source": "doc-id", "score": 0, "metadata": {}}
  ],
  "sources": [ /* identical array to references */ ],
  "evidence": [
    {"id": "ev-1", "doc_id": "doc-id", "source": "file.pdf", "snippet": "...(max 500 runes)", "metadata": {}}
  ],
  "grounding": {
    "status": "supported_by_retrieval",   // or "insufficient_evidence"
    "evidence_count": 3,
    "reason": "retrieval evidence gate rejected the candidates"  // only when insufficient
  },
  "session_id": "...",
  "trace_id": "...",
  "latency_ms": 1234,
  "trace": [ /* array of TraceStep, see below */ ]
}
```

`references` and `sources` are always the same content (both are kept for backward
compatibility). `ReferenceDocument.score` is currently always `0`. `tokens_used` exists in
the struct but is never populated. `grounding.status` is `insufficient_evidence` when the
retrieval evidence gate rejected the candidates or no evidence was returned.

`TraceStep` (also used in session message history and traces):

```json
{
  "trace_id": "...", "seq": 1,
  "type": "status",               // status | retrieval | rerank | context | rewrite | source | action | observation | guardrail | error | warning
  "stage": "request",
  "level": "", "summary": "...", "content": "...",
  "tool_name": "...", "tool_input": "...", "doc_id": "...",
  "latency_ms": 12, "token_count": 0, "error": "...",
  "metadata": {}
}
```

### `POST /api/v1/chat/stream` — SSE streaming

Auth required. Same request body. Response headers:
`Content-Type: text/event-stream`, `Cache-Control: no-cache`, `X-Accel-Buffering: no`.

Validation/auth errors (400/403/404) are returned as a normal JSON error envelope
*before* streaming starts (note: the SSE `Content-Type` header is already set by then, so
clients should check the HTTP status code rather than the content type). If the stream
fails to initialize, one SSE frame is sent with event name `error`:

```
event: error
data: {"type":"error","error":{"code":"internal","message":"...","trace_id":"..."}}
```

#### Frame format

All pipeline/agentic progress frames use event name `message`; the actual event kind is
in the `type` field of the JSON payload:

```
event: message
data: {"type":"content","content":"Hello","trace_id":"..."}
```

When the event channel closes, the server always emits one final frame with event name
`done` and empty data (`data: {}`). In a successful run a `{"type":"done"}` payload frame
*also* arrives first, so clients should treat either as terminal.

#### Event types (`data.type`)

Pipeline mode (`mode != "agentic"` or agent disabled):

| type | Extra fields | Meaning |
|---|---|---|
| `session_id` | `session_id`, `trace_id` | First frame when the request has/created a session |
| `rewrite` | `content` (rewritten query), `trace_step` | Query rewrite result (only when rewriting is on) |
| `trace` | `metadata`, `trace_step` | Retrieval observability. `metadata.stage` is `retrieved_candidates` (adds `query`, `chunks`, `count`), `rerank` (`before` or `after`), `context_build` (`chunks`, `count`, `context_chars`, `context_preview`), or `retrieval_gate` (`status`, `grounding_status`). `trace_step.type` is mapped: `retrieval` / `rerank` / `context` / `status` |
| `source` | `content`, `doc_id`, `metadata`, `trace_step` | One retrieved source document (one frame per source) |
| `content` | `content`, `doc_id` | Answer text delta; concatenate in arrival order |
| `error` | `content` (error text), `trace_step` | Pipeline failure. The message is in `content`, not `error` |
| `trace_snapshot` | `trace_snapshot` (array of TraceStep) | Full trace at completion; always sent, including after errors |
| `done` | `trace_id` | Normal completion |

Agentic mode (`mode: "agentic"` and agent enabled):

| type | Extra fields | Meaning |
|---|---|---|
| `session_id` | `session_id`, `trace_id` | Same as pipeline |
| `action` | `tool_name`, `tool_input` (JSON args string), `metadata.args_chars`, `trace_step` | Agent is calling a tool |
| `observation` | `tool_name`, `tool_input`, `content` (summarized result, max ~300 runes, prefixed `error: ` on failure), `latency_ms`, `metadata`, `trace_step`, `error` (on failure) | Tool result |
| `approval_required` | `approval_id`, `approval_status`, `action`, `risk_level`, `reason`, `expires_at` (RFC3339), `tool_name`, `tool_input`, `metadata`, `latency_ms`, `trace_step`, `content` | Tool call paused awaiting human approval |
| `approval_resolved` / `approval_rejected` / `approval_expired` | same fields as `approval_required`; `content` is the decision reason | Approval outcome |
| `warning` | `content` | Guardrail warning (e.g. repeated identical tool calls) |
| `sources` | `sources` (array of ReferenceDocument), `source_count` | Retrieved sources from the knowledge tool |
| `content` | `content` | Final answer, delivered as a **single** frame (agentic runs the ReAct loop non-streamed, so there is no token-by-token streaming) |
| `error` | `error` (string), `trace_step` | Fatal error; followed by `trace_snapshot`, no `done` payload frame |
| `trace_snapshot` | `trace_snapshot` | Full trace; always sent at the end |
| `done` | — | Normal completion |

Every frame includes `trace_id` when set. `trace_step` (a `TraceStep` object) is attached
to `status`, `rewrite`, `source`, `action`, `observation`, and `error` frames.

## 5. Sessions

All routes require auth. Sessions are owned per user; only global `admin` can read other
users' sessions (`403` otherwise, `404` if the session does not exist).

`Session` object:

```json
{
  "id": "...", "tenant_id": 1, "user_id": "...", "agent_id": "",
  "title": "...", "knowledge_base_ids": ["..."],
  "retrieval_config": {}, "similarity_threshold": 0.7, "top_k": 5,
  "created_at": "...", "updated_at": "..."
}
```

### `GET /api/v1/sessions`

Returns up to 100 sessions (no pagination params). Non-admin users see only their own.
`200`: `{"sessions": [Session, ...]}`. If the database is not connected:
`{"sessions": [], "message": "数据库未连接"}`.

### `POST /api/v1/sessions`

Request: `{"title": "...", "knowledge_base_ids": ["..."]}` (both optional).
`201`: the created `Session`. Defaults: `similarity_threshold: 0.7`, `top_k: 5`.
`knowledge_base_ids` are not validated against access rules at creation time.

### `GET /api/v1/sessions/{id}`

`200`: the `Session` object.

### `DELETE /api/v1/sessions/{id}`

`200`: `{"message": "删除成功"}`.

### `GET /api/v1/sessions/{id}/messages`

Returns the last 100 messages. `200`:

```json
{"messages": [ /* messageResponse */ ]}
```

`messageResponse` embeds the `Message` object plus extras:

```json
{
  "id": "...", "session_id": "...", "role": "user|assistant|system",
  "content": "...", "knowledge_references": {}, "agent_steps": [],
  "mentioned_items": {}, "tokens_used": 0, "latency_ms": 0, "metadata": {},
  "created_at": "...",
  "trace": [ /* TraceStep array, extracted from agent_steps.trace when present */ ]
}
```

When `agent_steps` contains a `trace` array, it is copied into both `trace` and
`agent_steps` (as TraceStep objects).

### `GET /api/v1/sessions/{id}/traces`

Query: `page`, `page_size` (default 20, max 100). `200`:

```json
{"traces": [ /* RequestTrace */ ], "total": 12, "page": 1, "page_size": 20}
```

Non-admin users only see their own traces. `RequestTrace`:

```json
{
  "id": "...", "trace_id": "...", "tenant_id": 1, "user_id": "...",
  "session_id": "...", "message_id": "...", "mode": "pipeline|agentic",
  "status": "completed|error", "latency_ms": 1234,
  "steps": [ /* TraceStep array (untyped any) */ ],
  "summary": {}, "error": "", "created_at": "...", "updated_at": "..."
}
```

`503` when the trace repository is not configured.

## 7. Approvals (human-in-the-loop)

Auth required. Approvals are created in-memory by the agentic loop when a sensitive tool
call needs confirmation (see SSE `approval_required`). Access rule: same tenant, and
either global admin or the owning user.

`Approval` object:

```json
{
  "approval_id": "...", "tenant_id": 1, "user_id": "...", "session_id": "...",
  "trace_id": "...", "source": "...", "action": "...", "tool_name": "...",
  "tool_input": "...", "reason": "...", "risk_level": "...",
  "metadata": {}, "status": "pending|approved|rejected|expired",
  "action_hash": "...", "created_at": "...", "expires_at": "...",
  "decided_at": "...", "decision_reason": "...", "decider_user_id": "..."
}
```

### `GET /api/v1/approvals/pending`

`200`: `{"approvals": [Approval, ...]}` — pending approvals visible to the caller.

### `GET /api/v1/approvals/{id}`

`200`: one `Approval`. `404` unknown id; `403` not yours.

### `POST /api/v1/approvals/{id}/decision`

Request: `{"decision": "approve|reject", "reason": "..."}`. `200`:

```json
{"type": "approval_decision", "approval_id": "...", "status": "approved", "decision": "approve"}
```

`400` for any other `decision` value or an invalid/late decision.

## 8. Knowledge bases

`KnowledgeBase` object (returned by create and embedded in list responses):

```json
{
  "id": "...", "tenant_id": 1, "name": "...", "description": "...",
  "mode": "vector",                         // "vector" (default) | "wiki"
  "embedding_model_id": "...",              // nullable
  "embedding_dimensions": 1536,
  "embed_model_fingerprint": "provider:model:dim",
  "chunking_config": {}, "extract_config": {},
  "document_count": 3, "chunk_count": 120,
  "created_at": "...", "updated_at": "..."
}
```

### `GET /api/v1/knowledge-bases`

Auth required; lists only KBs accessible to the caller. Query: `page`,
`page_size` (default 20, max 100). `200`:

```json
{
  "knowledge_bases": [ { "...KnowledgeBase fields...": "...", "embed_stale": false } ],
  "page": 1, "page_size": 20, "total": 3
}
```

Each item is the `KnowledgeBase` object plus `embed_stale` (bool): `true` when the KB was
indexed with a different embedding model fingerprint than the current config (never
`true` for a KB that was never indexed). If the database is not connected:
`{"knowledge_bases": [], "message": "数据库未连接"}` (HTTP 200).

### `POST /api/v1/knowledge-bases`

Auth required (no per-KB role needed). Request:

```json
{
  "name": "...",                    // required
  "description": "...",
  "mode": "vector",                 // "vector" | "wiki"; anything else → 400
  "embedding_model_id": "...",      // optional; empty string stored as NULL
  "embedding_dimensions": 1536,     // 0 → server default from config
  "chunking_config": {},
  "extract_config": {}
}
```

`201`: the created `KnowledgeBase` object.

### `GET /api/v1/knowledge-bases/{id}`

KB role: viewer. `200` (note: hand-built object, not the raw struct):

```json
{
  "id": "...", "tenant_id": 1, "name": "...", "description": "...",
  "mode": "vector", "embedding_model_id": "...", "embedding_dimensions": 1536,
  "embed_model_fingerprint": "...", "embed_stale": false,
  "chunking_config": {}, "extract_config": {},
  "document_count": 3, "chunk_count": 120,
  "created_at": "...", "updated_at": "..."
}
```

### `PUT /api/v1/knowledge-bases/{id}`

KB role: editor. Body: same shape as create (`name` required). This is a **full
overwrite** of `name`, `description`, `chunking_config`, `extract_config` only;
`mode`, `embedding_model_id`, and `embedding_dimensions` cannot be changed, and omitted
fields are reset to zero values. `200`: `{"message": "更新成功"}`.

### `DELETE /api/v1/knowledge-bases/{id}`

KB role: admin. Deletes the KB, its documents, vectors and import states.
`200`: `{"message": "删除成功"}`.

## 9. Knowledge graph (GraphRAG)

All three return `503 unavailable` when the GraphRAG service is not enabled.

### `GET /api/v1/knowledge-bases/{id}/graph`

KB role: viewer. Query: `limit` (default 200, max 1000 nodes). `200`:

```json
{
  "nodes": [{"id": "...", "label": "...", "degree": 3, "chunk_count": 2}],
  "edges": [{"source": "node-id", "target": "node-id", "label": "RELATION"}]
}
```

Returns `{"nodes": null, "edges": null}` when empty (zero-value struct).

### `POST /api/v1/knowledge-bases/{id}/graph/build`

KB role: editor. Synchronous full-graph build from all chunks of the KB. `200`:

```json
{
  "chunk_count": 120,
  "result": {
    "total_chunks": 120, "processed_nodes": 300, "processed_relations": 250,
    "failed_chunks": 0, "duration": 12345678900
  }
}
```

`duration` is a Go `time.Duration` serialized as **nanoseconds** (integer). `409` when the
KB has no chunks.

### `DELETE /api/v1/knowledge-bases/{id}/graph`

KB role: admin. `204 No Content`, empty body.

### `GET /api/v1/graphrag/status`

Auth required (any role). `200` when enabled:

```json
{"enabled": true, "neo4j_uri": "bolt://...", "connected": true}
```

When disabled: `{"enabled": false, "message": "GraphRAG 未启用"}` (still HTTP 200).

## 11. Documents (knowledge ingestion)

### `POST /api/v1/knowledge-bases/{id}/documents`

KB role: editor. `multipart/form-data` with field `file`. Behavior depends on the KB mode
and server configuration:

- **Wiki-mode KB**: the document is compiled by the LLM into wiki pages (synchronous).
  `200`: `{"message": "...", "page_count": 5, "link_count": 12, "knowledge_id": "...", "mode": "wiki"}`.
- **Import queue enabled** (normal mode): `202`:
  `{"message": "...", "knowledge_id": "...", "status": "pending", "replaced": false}`.
  A duplicate upload (same content hash) returns `200` with
  `{"message": "...", "knowledge_id": "...", "existing_knowledge_id": "...", "status": "...", "deduplicated": true}`.
- **Synchronous fallback** (no queue, no docreader): `200`:
  `{"message": "...", "chunk_count": 12, "knowledge_id": "...", "replaced": false}`.
  When parsing succeeded but embedding failed, still `200` with
  `{"message": "...", "chunk_count": 12, "status": "failed", "knowledge_id": "...", "error": "..."}`.

`replaced: true` means an existing document of the same name was re-imported
(incremental update). Poll `GET .../documents/{docId}/status` for async progress.

### `POST /api/v1/knowledge-bases/{id}/documents/url`

KB role: editor. JSON body:

```json
{"url": "https://...", "title": "...", "enable_multimodal": false}
```

`url` required; the URL is validated against the server-side SSRF/URL policy (`400` on
rejection). Response variants mirror the file upload endpoint (wiki-mode `200` with
`page_count`/`link_count`/`knowledge_id`/`mode`; queued `202` with
`knowledge_id`/`status`/`replaced`; sync `200` with `chunk_count`).

### `GET /api/v1/knowledge-bases/{id}/documents`

KB role: viewer. Query: `page`, `page_size` (default 50, max 200). `200`:

```json
{
  "documents": [
    {
      "id": "...", "filename": "a.pdf", "name": "...", "source_type": "file",
      "file_size": 12345, "file_type": "pdf", "file_path": "..." /* nullable */,
      "metadata": {}, "parse_status": "completed",
      "parse_error": null, "chunk_count": 12,
      "enrichment_status": "...", "enrichment_error": null, "enriched_chunk_count": 12,
      "created_at": "...", "updated_at": "...", "stage": ""
    }
  ],
  "page": 1, "page_size": 50, "total": 3
}
```

`source_type`: `file` | `faq` | `url`. `parse_status`: `pending` | `processing` |
`completed` | `failed`. Live fields (`stage`, in-flight status/error/counts) are overlaid
from the import task tracker when a task is running. If the DB is not connected:
`{"documents": [], "message": "数据库未连接"}` (HTTP 200).

### `GET /api/v1/knowledge-bases/{id}/documents/{docId}/status`

KB role: viewer. `200`:

```json
{
  "knowledge_id": "...", "knowledge_base_id": "...",
  "status": "processing", "stage": "embedding",
  "chunk_count": 0, "error": null,
  "enrichment_status": "...", "enrichment_error": null, "enriched_chunk_count": 0,
  "created_at": "...", "updated_at": "...",
  "enrichment_updated_at": "...", "started_at": "..."
}
```

`enrichment_updated_at` and `started_at` only appear while a live task state exists.
`404` when the document does not exist or belongs to another KB.

### `GET /api/v1/knowledge-bases/{id}/documents/{docId}/chunks`

KB role: viewer. `200`:

```json
{
  "chunks": [
    {"id": "...", "index": 0, "char_count": 512, "token_count": 0, "content": "..."}
  ],
  "total": 12
}
```

`token_count` is currently always `0`.

### `PATCH /api/v1/knowledge-bases/{id}/documents/{docId}/chunks/{chunkId}`

KB role: editor. Body: `{"content": "..."}` (required, non-empty after trim).
Edits the stored chunk text only; vectors are **not** rebuilt automatically. `200`:

```json
{
  "chunk": {"id": "...", "index": 0, "content": "...", "char_count": 512, "content_hash": "..."},
  "reindex_required": true
}
```

`404` when the chunk does not belong to this KB/document; `501` when chunk editing is not
enabled server-side (repository lacks the editor capability).

### `GET /api/v1/knowledge-bases/{id}/documents/{docId}/chunks/{chunkId}/revisions`

KB role: viewer. `200`:

```json
{
  "revisions": [
    {"id": "...", "chunk_id": "...", "content": "...", "content_hash": "...",
     "reason": "...", "created_at": "..."}
  ],
  "total": 2
}
```

### `POST /api/v1/knowledge-bases/{id}/documents/{docId}/chunks/{chunkId}/revisions/{revisionId}/restore`

KB role: editor. Restores the chunk content from a revision. `200`:
`{"chunk": Chunk, "reindex_required": true}` where `Chunk` is the full chunk object
(`id`, `knowledge_id`, `knowledge_base_id`, `chunk_index`, `content`, `content_length`,
`content_hash`, `parent_chunk_id`, `start_pos`, `end_pos`, `image_info`, `flags`,
`metadata`, `created_at`). `404` for unknown chunk/revision; `501` when unsupported.

### `POST /api/v1/knowledge-bases/{id}/documents/{docId}/chunks/{chunkId}/reindex`

KB role: editor. Re-embeds and upserts only this chunk from its current stored content.
`200`: `{"chunk_id": "...", "indexed": true}`. `503` when embedding/vector components are
disabled; `502` on embedding provider failure.

### `POST /api/v1/knowledge-bases/{id}/documents/{docId}/reindex`

KB role: editor. Full re-parse + re-embed of the document from its original source (URL
or still-existing uploaded file). Old vectors and chunks are cleared first.
`202`: `{"message": "...", "doc_id": "..."}`. Errors: `409` if the document is currently
`processing`; `400` when the original source is unavailable (file cleaned up) or the
source type is unsupported.

### `POST /api/v1/knowledge-bases/{id}/documents/{docId}/sync`

KB role: editor. Incremental sync: refetches the source content, diffs chunk hashes, and
only re-embeds changed chunks. If the document hash is unchanged, `200`:

```json
{"message": "文档内容未变化，跳过同步", "doc_id": "...", "skipped": true, "added": 0, "removed": 0, "retained": 12}
```

Otherwise the sync runs in the background and `202` is returned:
`{"message": "...", "doc_id": "..."}`. `409` while `processing`; `400` when the source
content cannot be fetched.

### `DELETE /api/v1/knowledge-bases/{id}/documents/{docId}`

KB role: editor. Deletes the document record, its wiki pages (wiki KBs), and its vectors.
`200`: `{"message": "删除成功"}`.

## 12. Models

Model entries are runtime configuration slots (one per type), not a database table.

### `GET /api/v1/models`

Auth required (any role). `200`:

```json
{
  "models": [
    {"id": "llm-default", "name": "gpt-4o", "type": "llm", "provider": "openai",
     "is_default": true,
     "config": {"base_url": "...", "temperature": 0.7, "max_tokens": 4096}},
    {"id": "embedding-default", "name": "text-embedding-3-small", "type": "embedding",
     "provider": "openai", "is_default": true,
     "config": {"base_url": "...", "dimensions": 1536}},
    {"id": "reranker-default", "name": "...", "type": "reranker", "provider": "...",
     "is_default": true,
     "config": {"base_url": "...", "top_k": 5, "threshold": 0.5}}
  ]
}
```

The reranker entry is present only when the reranker is enabled.

### `POST /api/v1/models`

Role: admin. Creates or replaces the slot for the given type. Request:

```json
{
  "type": "llm",            // required: "llm" | "embedding" | "reranker"
  "provider": "openai",     // required
  "model": "gpt-4o",        // required
  "base_url": "...", "api_key": "...",
  "temperature": 0.7,       // llm only; 0 keeps current
  "dimensions": 1536,       // embedding only; 0 keeps current
  "top_k": 5, "threshold": 0.5  // reranker only; 0 keeps current
}
```

An `api_key` containing `****` is treated as "unchanged" (the masked value returned by
GET endpoints). For `llm`/`embedding` the provider is instantiated immediately and the
chat service is reloaded; `400` when initialization fails. Selecting `reranker` also
enables it. `201`: `{"message": "...", "id": "llm-default"}` where `id` is
`<type>-default`.

### `DELETE /api/v1/models/{id}`

Role: admin. `llm-default` and `embedding-default` return `400` (update via
`PUT /settings` instead). `reranker-default` disables the reranker; `200`:
`{"message": "Reranker 已禁用"}`. Any other id: `404`.

### `PUT /api/v1/settings`

Role: admin. Partial update — every field is optional; only present fields change.
Request shape:

```json
{
  "rag": {"top_k": 5, "enable_hybrid": true, "enable_rewrite": true,
          "enable_rerank": true, "chunk_size": 500, "chunk_overlap": 50},
  "llm": {"provider": "...", "model": "...", "base_url": "...", "api_key": "...",
          "temperature": 0.7, "max_tokens": 4096},
  "embedding": {"provider": "...", "model": "...", "base_url": "...", "api_key": "..."},
  "reranker": {"enabled": true, "provider": "...", "model": "...", "base_url": "...",
               "api_key": "...", "top_k": 5, "threshold": 0.5},
  "agent": {"enabled": true, "max_steps": 10,
            "enable_knowledge_tool": true, "enable_web_search": true},
  "graphrag": {"enabled": true, "extract_temperature": 0.0, "top_k": 5}
}
```

Validation limits (all violations → `400`): `rag.top_k` 1-100, `rag.chunk_size`
50-10000, `rag.chunk_overlap` 0-5000 and `< chunk_size`, `agent.max_steps` 1-50,
`llm.temperature` 0-2, `llm.max_tokens` 1-128000, `reranker.top_k` 1-50,
`reranker.threshold` 0-1, `graphrag.extract_temperature` 0-2, `graphrag.top_k` 1-50.
Masked `api_key` values (containing `****`) are ignored. Setting `llm.api_key` also
fills `embedding.api_key` when the embedding key is empty.

The update is transactional: dependent providers (embedding / LLM / reranker) are rebuilt
from the candidate config before commit, and on failure the running config is untouched
(`502` for embedding/LLM rebuild failure, `400` for reranker). `200`:

```json
{"message": "已更新 3 项设置", "changed": ["llm.model", "rag.top_k"], "warnings": ["..."]}
```

`changed` is a list of dotted setting names. `warnings` is present but may be empty/null;
changing the embedding model adds a warning that existing vectors must be re-indexed.
When nothing changed: `{"message": "无变更", "changed": null}`. If runtime update
succeeded but persisting the config file failed: `500` with
`{"error": "...", "changed": [...]}` (note: this particular failure does **not** use the
standard error envelope).

## 19. Known quirks (relevant to clients)

These behaviors are documented as-is; they may be cleaned up server-side later:

1. **SSE terminal `done` is sent twice in spirit**: a `{"type":"done"}` payload frame,
   then a bare `event: done` frame with `{}` when the channel closes. Treat the first
   terminal frame you see as the end.
2. **Pipeline `error` frames carry the message in `content`**, while service-level
   `error` frames carry it in `error`. Check both fields.
3. **After a pipeline error**, no `done` payload frame is sent, but the trailing bare
   `event: done` frame still arrives; the server also still saves a (possibly empty)
   assistant message and records the request trace as `completed`.
4. **Agentic `content` arrives as one frame** (the ReAct loop runs non-streamed), unlike
   pipeline mode which streams deltas.
5. `ChatResponse.references` and `ChatResponse.sources` are always identical;
   `ReferenceDocument.score` is always `0`; `tokens_used` is never set.
6. `PUT /api/v1/settings` persistence failure returns `{"error": "...", "changed": [...]}`
   instead of the standard error envelope.
7. `GET /knowledge-bases/{id}/graph` returns `{"nodes": null, "edges": null}` when empty.
8. `BuildGraphResult.duration` is nanoseconds (Go `time.Duration` JSON encoding).
9. Session creation does not validate `knowledge_base_ids`; `GET /sessions` and
   `GET /sessions/{id}/messages` are hard-capped at 100 entries with no pagination.
10. `ChatRequest.top_k` and `temperature` are accepted but currently ignored by the
    chat service.
